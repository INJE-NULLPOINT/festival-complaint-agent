# 사람 확인 체크리스트 (15분)

> 사용자가 직접 브라우저·폰으로 한 바퀴 돌려 D5-4 · D5-14 · D5-18 을 끝내는 한 장입니다.
> 전제: `python scripts/run_all_servers.py` 가 이미 돌고 있음(webapi 8765 · worker · 웹 5173).
> 2026-09-30 저녁 기준 참모 작성. 자동 점검(헤드리스)은 이미 통과했고, 이 장은 **사람 눈으로만 볼 수 있는 것**만 봅니다.

## 0. 시작 전 1분 — 꼭 먼저 (막히는 원인 1순위)

지금 돌고 있는 서버는 **운영자 코드가 설정되지 않은 상태**입니다(09-30 저녁 확인: 코드 확인 요청에 403). 이대로는 지우기·요청서·상태 변경이 전부 거부돼 3번 이후를 못 합니다.

1. `festival_agent/.env` 파일을 엽니다(없으면 `.env.example`을 복사해 이름을 `.env`로).
2. `ADMIN_CODE=` 뒤에 직접 정한 코드를 적습니다. `LLM_BACKEND=claude_code` 줄도 있는지 봅니다. 코드는 채팅·문서에 적지 않습니다.
3. `run_all_servers.py` 창에서 `Ctrl+C` → 같은 명령으로 다시 켭니다(총괄에게 부탁해도 됩니다).
4. 확인: 웹 화면 맨 위에 `실시간 · 로컬 DB`, `AI: Claude Code (개발용)` 배지가 보이면 준비 끝.

> 폰 확인(3장)을 할 거면 다시 켤 때 `python scripts/run_all_servers.py --phone` 으로 켭니다(웹이 5173 대신 폰용 빌드 4173으로 뜸). 5173 화면도 필요하면 폰 확인 뒤 옵션 없이 다시 켭니다.

## 1장. 웹 화면 1바퀴 — D5-14 (약 6분)

PC 브라우저에서 엽니다. `--phone`으로 켰으면 5173 대신 `http://127.0.0.1:4173`입니다.

| 순서 | 주소 · 누를 것 | 통과 기준 |
|---|---|---|
| 1 | `http://127.0.0.1:5173/?v=qr&zone=유등터널` | 머리에 축제 이름·`불편 신고`, 위치가 `유등터널`로 미리 골라져 있음. 관리자 배지·탭이 **없음** |
| 2 | 내용 칸에 `...` 만 적고 `접수하기` | `어떤 불편인지 조금 더 적어 주세요`가 뜨고 접수 안 됨 |
| 3 | `유등터널 입구에 사람이 몰려서 밀려요` 적고 `접수하기` | `보내는 중…` → `접수되었습니다` 안내창, `W-숫자` 접수번호 |
| 4 | 새 탭 `http://127.0.0.1:5173/#control` | 실시간 유입 맨 위에 방금 민원 + 같은 `W-숫자`. 처음엔 `분류 중` |
| 5 | 30초쯤 기다림 | 그 행이 `혼잡`(또는 안전 계열)으로 바뀜. 조치할 일 카드에 유등터널 카드가 보임 |
| 6 | 1번 카드의 `계산식 보기` | 계산식이 펼쳐짐 |
| 7 | 실시간 유입에서 방금 민원 행의 휴지통 | **운영자 코드 창**이 뜸 → 0단계 코드 입력 → 행이 사라지고 `지웠습니다 · 되돌리기`(5초) |
| 8 | 5초 안에 `되돌리기` | 행이 다시 나타남 |
| 9 | 1번 카드의 `혼잡 전체 요청서 생성` | `…조치요청서 작성을 요청했습니다`. 1~2분 안에 요청서 상태가 생김 |
| 10 | 위 탭 `조치` → 방금 요청서 `미리보기` → `DOCX` | 미리보기에 원문 인용·부서·계산식, DOCX 파일이 내려받아짐 |
| 11 | 요청서 상태를 `조치중` → `완료` | 모양이 ◐ → ✓ 로 바뀜. 관제로 돌아가면 그 카드가 `조치 완료` 묶음으로 내려감 |
| 12 | 관제 `확인 필요 N` 버튼(있으면) | 처리 패널이 열림. 한 건 `유형 없음으로 닫기` → 목록에서 빠짐 |

- 12번은 확인 필요 민원이 없으면 건너뜁니다(없으면 `처리할 확인 필요 민원이 없습니다.`).
- 2번에서 운영 DB에 민원 2건(3번·확인용)이 실제로 들어갑니다. 끝나고 지우기(7번 방식)로 정리해도 됩니다.

## 2장. Streamlit 1바퀴 — D5-4 (약 4분)

새 터미널(`festival_agent` 폴더)에서:

```powershell
streamlit run app.py
```

브라우저가 `http://localhost:8501`로 열립니다.

| 순서 | 누를 것 | 통과 기준 |
|---|---|---|
| 1 | 왼쪽 `접수` 페이지 → 구역 고르고 한 줄 적어 제출 | 성공 안내 |
| 2 | `관제` 페이지 | 사이드바 백엔드 표시가 `claude_code`, 방금 민원이 유입에 보이고 잠시 뒤 유형이 붙음(자동 갱신 5초) |
| 3 | `관제` 의 '지금 조치할 일' 카드 · 확인 필요 목록 | 카드가 보이고, 확인 필요는 보기만 가능 |
| 4 | `조치` 페이지 → 사이드바 `운영자 코드` 입력 → `확인` | `운영자 모드`로 바뀌고 요청서 생성·상태 변경·확인 필요 처리 버튼이 나타남 |
| 5 | 요청서 하나 상태 바꾸기, 확인 필요 한 건 처리 | 바뀐 값이 표에 반영 |
| 6 | 사이드바 `운영자 잠금` | 버튼들이 다시 사라짐 |

## 3장. 실제 폰 — D5-18 (약 5분)

- 0단계에서 `--phone`으로 켰는지 확인합니다.
- 폰과 PC를 같은 Wi-Fi에 둡니다.
- PC 주소는 09-30 저녁에 `192.168.0.24`였습니다. 바뀌었을 수 있으니 PC에서 `ipconfig`의 IPv4 주소를 봅니다.

| 순서 | 폰에서 | 통과 기준 |
|---|---|---|
| 1 | `http://192.168.0.24:4173/?v=qr&zone=4` (주소는 위 확인값) | 접수 화면이 뜨고 위치가 미리 골라져 있음. **가로로 밀리지 않음**(옆으로 스크롤 안 됨) |
| 2 | 위치 줄 누르기 | 구역 목록이 폰 기본 선택 창으로 뜸 |
| 3 | 내용 입력 칸 누르기 | 화면이 확대되지 않음(글자 16px 이상), 키보드가 버튼을 가리지 않음 |
| 4 | 한 줄 적고 `접수하기` | 안내창이 아래에서 올라오고 `한 건 더 접수`·`닫기`가 손가락으로 눌림 |
| 5 | 폰을 가로로 돌림 | 화면이 깨지지 않음 |
| 6 | (가능하면) 다른 폰·다른 브라우저 1대 더 | 같은 결과 |

- 폰 기종과 브라우저(예: 갤럭시 S○ · 삼성 인터넷)를 적어 둡니다. 확인서와 보고서에 씁니다.

## 막히면

1. 그 화면을 **캡처**합니다. 폰은 스크린샷을 찍어 PC로 옮깁니다.
2. 캡처를 `제출_준비/사람확인/` 폴더에 `장번호-순서_무엇.png`로 넣습니다. 예: `1-7_코드창안뜸.png`. 폴더가 없으면 만듭니다.
3. 총괄 세션에 한 줄로 알립니다. 예: "1장 7번 막힘, 캡처 1-7_코드창안뜸.png".
   - 총괄이 서버·화면 담당에게 넘깁니다.
   - 서버 로그는 `festival_agent/output/logs/`(webapi.log · worker.log · vite.log)에 있어 총괄이 같이 봅니다.
4. 막힌 순서만 건너뛰고 다음으로 갑니다. 한 칸 때문에 전체를 멈추지 않습니다.
