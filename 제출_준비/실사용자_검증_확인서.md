# 실사용자 검증 확인서

> **설명회 Q7**: "실사용자 검증은 필수는 아니지만 **실제 사용자 3명 이상** 또는 기관 담당자 피드백을 증빙하면 **+1점 가점**을 받을 수 있습니다."
> 증빙 요건: **피드백 내용 + 이름/소속 + 검증일자**
>
> 참여자는 **팀원이 아닌 사람 3명 이상**입니다. 1인당 약 10분이 걸립니다. **D6(10/4)에 수행**하세요.

## 성공 기준 (검증 전에 확정 · 결과가 못 미쳐도 그대로 적음)

> 3명은 통계가 아니라 **사용성 확인**입니다. 결과를 숫자로 일반화하지 않습니다.

| # | 기준 | 측정 방법 |
|---|---|---|
| S1 | T1 접수를 3명 모두 **도움 없이** 완료, 소요 시간 중앙값 **60초 이내** | 운영자 스톱워치(QR 스캔 → 제출) |

| S3 | T2 본인이 뜻한 유형과 시스템 분류가 같음: 3명 중 **2명 이상** | 참여자 본인 답(Q5-가를 결과 보기 전에 적고 Q5-나와 비교) |
| S4 | T3 참여자가 적은 첫 행동이 1번 카드 '해야 할 일' 중 하나와 같은 취지: 3명 중 **2명 이상** | 운영자가 판정합니다. 참여자 원문과 카드 문구를 보고서에 나란히 실어 심사자가 직접 확인할 수 있게 합니다 |
| S5 | Q1 접수 용이성·Q3 납득도 평균 **4 / 5 이상** | 참여자 본인 답 |

## 진행 순서 (운영자용 · 당일 체크)

> 이 절은 운영자(팀)가 보는 준비 목록입니다.
> **운영자는 시스템 값과 관찰 사실만 적습니다.** 성명·소속·동의·점수·의견·답·서명은 **참여자 본인만** 씁니다.
> 말로 답하면 참여자에게 직접 적어 달라고 요청합니다. 받아 적거나 요약해서 대신 쓰지 않습니다.

**사전 준비**
- [ ] 검증용 **별도 DB**로 켭니다. 시연·평가 데이터와 섞이지 않게 `DB_PATH`를 새 파일로 지정합니다.
  - 워커 · `webapi.ts` · 웹 서버를 켭니다 (`node server/scripts/run_all_servers.ts --phone` 한 줄). 폰 접속용은 `npm run phone`(구형 브라우저 대응 빌드)입니다.
- [ ] **배경 데이터**를 미리 넣습니다. 참여자 민원 1건만 있으면 관제 1번 카드가 없을 수 있기 때문입니다.
  - 개발용 **합성 시드** 일부를 리플레이해 같은 배경 상황을 만듭니다. 결과 보고서에 '배경 데이터는 개발용 합성 시드이며, 참여자가 제출한 민원만 실제 입력'이라고 **반드시 밝힙니다**.
  - 배경을 넣은 DB 파일을 복사해 **스냅샷**으로 둡니다. 참여자마다 시작 전에 이 스냅샷으로 되돌려, 모두 같은 1번 카드를 보게 합니다.
- [ ] 폰과 PC가 **같은 Wi-Fi**인지 확인합니다. PC 주소가 바뀌었으면 관리자 화면 **'접수 QR'(QR 만들기)** 에 새 주소(`http://<PC주소>:<포트>`)를 넣어 QR을 다시 만듭니다.
- [ ] 'QR 만들기'에서 **인쇄**를 눌러 A4로 뽑습니다(또는 화면에 띄웁니다). QR은 한 장이고 구역은 참여자가 화면에서 고릅니다.
- [ ] 운영자 폰으로 QR 1장을 먼저 찍어 접수 → 관제 반영까지 한 번 확인합니다.
- [ ] 관제 화면(`/#control`)을 참여자가 볼 수 있는 화면에 띄웁니다.
- [ ] 참여자가 안전·혼잡 민원을 쓰면 **즉시 알림이 뜰 수 있다**고 미리 안내합니다.

**참여자 1명당 (약 10분)**
1. **목적 설명:** "축제 불편 신고를 받아 AI가 분류하고, 무엇부터 조치할지 정리하는 시스템을 시험합니다."
   - 성명·소속을 가점 증빙에 쓴다는 점을 안내하고 동의를 받습니다.
2. **T1 접수:** 참여자가 구역 QR을 **본인 폰으로** 찍고, 본인이 정한 불편 1건을 **도움 없이** 제출합니다.
   - 문장은 참여자가 정합니다. 예시를 불러 주지 않습니다.
   - 운영자는 스톱워치로 시간을 잽니다.
   - 제출 직후, 결과를 보기 **전에** 참여자가 **Q5-가**(제가 뜻한 유형)를 적습니다.
3. **T2 결과 확인:** 참여자가 관제 화면에서 자기 민원을 찾고, 시스템 분류를 **본인이** Q5-나에 적습니다.
4. **T3 카드 읽기:** 참여자가 관제 1번 카드('지금 조치할 일')를 30초 보고, '담당자라면 가장 먼저 무엇을 하겠는가'를 **본인이** Q6에 적습니다.
5. **순위 설명:** 아래 고정 문구를 3명 모두에게 **똑같이** 읽고, Q3 납득도를 답받습니다.
   > "건수는 주차가 많지만, 다칠 수 있는 민원은 가중치가 붙어 위로 올라갑니다. 순위를 누르면 계산식이 보입니다."
6. 참여자가 Q1~Q6와 서명을 **직접** 적습니다.
7. **촬영:** 제출 장면과 반영된 관제 화면(시각이 보이게)을 찍습니다. 얼굴 촬영은 동의자만 합니다.
