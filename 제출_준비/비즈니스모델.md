# 비즈니스 모델 — 발표자료 1장 분량

> **심사 배점 10점** (사업성, 사회 활용성). 발표자료 10장 중 **1장**, 본선 "발전계획·비즈니스모델 30초" 구간에서 말합니다.
> 숫자 규칙(2026-10-01 D5-67): 공개 자료는 **원문을 연 것만** 링크와 함께 쓰고, 우리가 계산·가정한 값은 **(추정)** 을 붙입니다. 원가 칸은 **API 실측 후** 채웁니다. 링크는 '출처' 절에 번호로 모았습니다.

## 한 문장

**축제마다 새로 만드는 게 아니라, 설정만 바꿔 다음 축제로 넘기는 구조다.**
지역축제는 2024년 1,170개(경남 135개)[1], 2025년 1,214개[2]로 늘고 있다. 축제마다 민원 대응 체계를 새로 꾸린다는 것은 우리 가정이다 (추정 — 시군 결과보고서로 확인하지 못함).

## 2. 수익 모델 — 행사 단위 라이선스

| 상품 | 범위 | 단가(안) · 근거 |
|---|---|---|
| **행사 패키지** | 축제 1회(3~10일) · QR 구역 무제한 · 대시보드 1식 | **실증 후 확정.** 비교 기준 ① 사람 대체 비용: 현장 접수 인력 2명 × 10일 × 일당 82,560원(최저임금 10,320원[11] × 8시간) = 약 165만 원 (추정 — 인원·일수는 가정) ② 공공 AI 민원 서비스 규모: 경기 광주시 AI 민원 챗봇·콜봇 사업에 도비 5억6천만 원 확보[12] (총사업비 아님, 상시 민원용이라 직접 비교 불가) |
| **연간 구독** | 시군 단위 · 연중 행사 + 상시 민원 | **실증 후 확정.** 시군당 평균 축제 7.5개(추정, 위 1절) × 행사 패키지. 근거 없는 할인율은 두지 않음 |
| **초기 설정** | 구역·부서 매핑, 분류 라벨 | 작업 일수 〔 〕 × 응용SW개발자 일평균임금 378,250원(2026년 적용)[13]. 작업 일수는 '다른 축제 설정으로 바꾸기' 리허설 때 재서 채움 |

> 단가는 **근거가 있는 비교 기준만** 적고, 금액은 실증 뒤 정합니다. 근거 없는 숫자는 "데이터·안전·윤리"에서 감점 위험이 있습니다.

## 3. 원가 구조 — 우리가 실제로 계산할 수 있는 숫자

변동비는 **LLM 호출 비용이 대부분**이라고 가정합니다(추정). 여기에 Supabase 요금이 더해집니다: Free $0(DB 500 MB), Pro 월 $25부터(디스크 8 GB·전송 250 GB·파일 100 GB 포함)[14]. 사용 중인 플랜은 [확인 필요]이고, 민원 1,000건 규모는 Pro 포함 사용량 안에 든다고 봅니다(추정). 웹은 정적 빌드라 호스팅 비용은 방식에 따라 다릅니다.

모델 단가: `claude-opus-5-5` 100만 토큰당 입력 $4 · 출력 $20 (Batch API 는 50% 할인)[15].

원가는 **민원 수에 비례하는 몫**(①분류), **시간에 비례하는 몫**(⓪계획·②감시·④통합은 주기마다 돎), **요청서 수에 비례하는 몫**(③조치)으로 나눕니다.

```
축제 1회 원가  C = N × (1 − h) × a  +  K × b  +  D × d

  N  민원 건수                     (아래 표의 가정 1,000건)
  h  분류 캐시·기억 적중률          API 실측 후
  a  분류 1건 원가                  CLI 참고 <!--n:cost_classify-->$0.01328<!--/n-->   ※ (옛 방식 A안 기준 — 지금 기본 B′ 는 호출 1회라 달라짐)
  K  실제로 돈 배후 주기 수          API 실측 후 (운영 시간 ÷ 주기 1분 × (1 − ④ 건너뜀 비율))
  b  배후 1주기(②감시 + ④통합) 원가  CLI 참고 $0.1878    ※ ($0.0930 + $0.0948)
  D  조치요청서 건수                API 실측 후
  d  요청서 1건 원가                CLI 참고 $0.0877    ※ ($0.1753 ÷ 2건)
  원화 환산                          API 실측 후 (환율·기준일 함께 적음)

  ※ 출처: 원가측정_참고.md (2026-09-30 15:31) — Claude Code CLI 경유 참고값 · 합성 시드 · 1주기 1회 측정.
    API 직접 호출과 금액이 다르므로 제출용 값은 `--backend anthropic` 실측으로 바꿉니다.
```

> ⚠ 원가측정_참고의 **"민원 1건당 $0.08590"에 민원 수를 곱하면 안 됩니다.** 한 주기 전체 비용($0.4295)을 그 주기에 분류한 5건으로 나눈 값이라 민원 수에 따라 오르내립니다.
>
> **읽을 점:** 배후 1주기가 약 $0.19(CLI 참고)라 1분 주기로 오래 돌리면 배후 몫이 분류 몫보다 커질 수 있습니다. 원가를 좌우하는 것은 **배후 주기 간격과 ④ 건너뜀 장치**이고 둘 다 설정으로 조정합니다.

| 항목 | 값 | 비고 |
|---|---|---|
| 민원 1건당 평균 토큰 | API 실측 후 | <sub>CLI 참고(옛 방식): 분류 5건 평균 입력 843 · 출력 304 · 캐시 읽기 2,332</sub> |
| 민원 1건 원가 | API 실측 후 | a × 환율 |
| 분류 캐시·기억 적중률 | API 실측 후 | <sub>합성 시드는 반복 문장이 많아 적중률이 부풀려지므로 쓰지 않음. 실제 운영 데이터가 생기면 측정</sub> |
| 축제 1회(민원 1,000건 가정) 원가 | API 실측 후 | <sub>지금 계산되는 것은 분류 몫뿐: 1,000 × $0.01328 = $13.28 (캐시 0 가정 · CLI 참고 · 추정)</sub> |

**제안 단가의 논리.** 하한 = 원가 C + 초기 설정(작업 일수 × 공표 단가[13]) / 상한 = 사람 대체 비용 또는 비슷한 공공 계약가. 두 쪽 모두 근거가 있을 때만 범위로 쓰고 한쪽만 있으면 그쪽만 씁니다. 운영 지원비·마진·할인율은 근거가 없어 두지 않습니다.

> **측정 방법**: `server/core/db.ts` 의 `agent_log` 에 호출별 지연과 토큰이 남습니다. API 키로 `node server/scripts/measure_cost.ts` 를 돌리면 a·b·d 가 에이전트별로 나와 **"민원 1건 분류 원가 ○원 + 배후 1주기 ○원"** 을 숫자로 말할 수 있습니다.

## 4. 시장과 확장 경로

```
1단계  축제 1개 (진주남강유등축제)          ← 대회 제출 범위
   ↓   구역·부서 매핑만 교체
2단계  경남 시군 축제로 수평 확장            (경남 18개 시군, 축제 135개 — 2024)
   ↓   분류 라벨 교체
3단계  지자체 상시 민원 (도로·환경·소음)      (지자체 AI 민원 챗봇 도입 중: 포항·세종·시흥[16], 경기 광주[12])
   ↓
4단계  대학 축제, 체육대회, 박람회 등 대규모 행사 일반
```

**확장이 싼 이유**: 구역·부서 매핑·분류 라벨을 **설정 데이터로 분리**했습니다(`server/core/config.ts` 의 `ZONES` / `DEPARTMENT_MAP` / `LABELS`). 코드 수정 없이 교체됩니다. 발표 때 **다른 축제 설정으로 바꿔 실행하는 장면**을 넣으면 확장성 주장이 증거가 됩니다.

## 5. 사회적 가치 (수익 외)

- **안전 사고 예방** — 건수에 묻히던 안전 민원이 3건에서 드러난다
- **행정 신뢰** — 방문객 민원이 실제 조치로 연결되는 경로가 생긴다
- **데이터 축적** — 축제별 민원 이력이 다음 해 기획의 근거가 된다
