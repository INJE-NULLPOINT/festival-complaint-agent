# 평가셋 라벨링 가이드 (D6-3)

실제 리뷰 평가셋(`scripts/templates/eval_labels_template.csv` 형식)의 정답을 **사람 2명이 따로** 붙이기 위한 안내입니다.
정답은 사람만 붙입니다. 모델의 결과를 먼저 보지 않고, 합성 시드(`seed/dev_sample.csv`)는 평가셋에 넣지 않습니다.

## 1. 진행 순서

1. 수집한 글(`실제리뷰_수집가이드.md`)을 템플릿 CSV 에 옮깁니다. 열: `text, zone, posted_at, source_url, source_name, label_a, label_b, label_final, note`.
   `source_url` 이 없는 행은 측정에서 빠집니다 (출처 없는 글은 근거가 안 됩니다).
2. **라벨러 A·B 가 서로 보지 않고** 각자 `label_a`, `label_b` 만 채웁니다. 모델 결과·상대 라벨을 미리 보지 않습니다.
3. 두 사람이 끝나면 `label_a ≠ label_b` 인 행만 모아 협의하고, 합의한 값을 `label_final` 에 적습니다. 일치한 행은 그 값을 그대로 `label_final` 에 넣습니다.
4. 합의하지 못한 행은 `label_final` 을 **비워 둡니다** (측정에서 제외되고 제외 건수가 보고서에 남습니다). 억지로 정하지 않습니다.
5. 측정: `python scripts/measure_accuracy.py --backend anthropic --labels <파일>.csv --repeat 3`
   결과의 `Cohen's κ`(라벨러 간 일치도)와 불일치 건수를 보고서에 함께 적습니다.
6. 측정한 뒤에 정답을 고치지 않습니다. 프롬프트도 측정 전에 고정하고, 평가셋의 문장은 프롬프트·테스트에 넣지 않습니다.

## 2. 유형 정의 (하나만 고릅니다)

| label | 뜻 | 고르는 경우 |
|---|---|---|
| `parking` 주차/교통 | 주차장·진입로 정체·셔틀·대중교통 | 차를 대기 어렵다, 길이 막힌다, 셔틀이 안 온다 |
| `restroom` 화장실 | 화장실 수·청결·대기 | 줄이 길다, 휴지가 없다, 더럽다 |
| `price` 가격/바가지 | 음식·체험 가격, 바가지 | 가격이 비싸다, 표시와 다르게 받는다 |
| `guide` 안내/동선 | 표지판·안내·길 찾기·정보 부족 | 길을 헤맸다, 시간표를 알 수 없다 |
| `crowd` 혼잡 | **원인이 사람**: 인파 밀집·몰림·밀림·병목·일행을 잃어버림 | 다리에 사람이 몰렸다, 떠밀렸다 |
| `safety` 안전 | **원인이 시설·환경의 결함**: 조명 없음·난간 흔들림·미끄러움·파손·구조물 위험 | 어두워 넘어졌다, 난간이 흔들린다 |
| `positive` 긍정 | 칭찬·만족 | 좋았다, 또 오고 싶다 |

글 하나에 불만이 여러 개면 **글쓴이가 가장 크게 탓하는 것**의 유형을 고릅니다. 애매하면 `note` 에 이유를 적습니다.

## 3. 안전 판정 기준 (가장 중요합니다)

평가의 주지표는 **안전 재현율**(안전인 글을 놓치지 않았는가)입니다. 그래서 안전 라벨이 가장 신중해야 합니다.

- **원인 기준으로 고릅니다.** "위험했다", "다칠 뻔했다"는 말이 있어도 원인이 **인파**면 `crowd`, **시설·환경의 결함**이면 `safety` 입니다. 사람이 적어도 생길 위험이라면 `safety` 입니다.
- 이 평가는 **정답 라벨이 `safety` 인 글만** 안전 글로 셉니다. 인파 때문에 위험했던 글은 `crowd` 라벨이 되어 안전 건수에 들어가지 않습니다 (모델은 그런 글에 안전 의심 표시를 따로 합니다). 이 차이를 보고서에 적어 둡니다.
- 신체적 위험(넘어짐·부상 위험·압사 우려·시설 파손)이 글에 **드러나 있을 때만** 안전입니다. 단순 불편(줄이 길다, 비싸다, 불친절)은 안전이 아닙니다.
- 위험이 "있을 것 같다"는 추측만 있고 구체적 근거가 없으면 안전으로 키우지 않고 다른 유형으로 고른 뒤 `note` 에 적습니다.
- 안전 정답은 **최소 20건(목표 30건)** 이 있어야 신뢰구간이 의미를 갖습니다. 부족하면 안전·혼잡 글을 더 수집합니다.

## 4. 라벨을 붙일 수 없는 글

- 내용이 없는 글(기호·의미 없는 글자), 광고·스팸, 축제와 무관한 글은 **평가셋에 넣지 않습니다** (행을 만들지 않습니다).
- 민원인데 위 7유형 어디에도 넣기 어려우면 `label_final` 을 비우고 `note` 에 이유를 적습니다. 모델은 이런 글을 `확인 필요`로 넘기는 것이 정상이라, 평가셋에서는 제외하되 제외 건수를 기록합니다.
- 개인정보(전화번호·이름 등)는 옮기기 전에 지웁니다.

## 5. 불일치 협의 방법

1. 행마다 각자 **고른 이유를 한 줄**로 말합니다 (정답을 설득하는 자리가 아닙니다).
2. 위 정의표·안전 기준(원인 기준)에 비추어 더 맞는 쪽으로 합의합니다. 다수결이나 윗사람 의견으로 정하지 않습니다.
3. 합의한 이유를 `note` 에 적습니다. 같은 패턴이 반복되면 이 가이드에 기준을 덧붙이고, **이미 라벨한 행은 새 기준으로 다시 훑되 모델 결과는 보지 않습니다.**
4. 끝내 갈리면 `label_final` 공란. 불일치 건수와 κ 는 합의 **전**의 `label_a`·`label_b` 로 계산됩니다 (협의 결과가 κ 를 부풀리지 않습니다). 단 `label_final` 이 빈 행은 평가셋에서 빠지므로 κ 에도 들어가지 않습니다.

## 6. 측정 결과를 적을 때 (보고서 문구)

- 합성 32건 측정값(32/32, 안전 4/4)은 **개발용 참고값**입니다: 정확도 95% 신뢰구간 [89%, 100%], 안전 재현율 [51%, 100%] — 실제 평가셋으로 재측정해야 합니다.
- 실제 평가셋 결과는 `정확도 · Wilson 95% CI · 안전 재현율 · CI · 반복 평균/편차 · κ · 제외 건수(출처 없음·합의 없음·중복)` 를 함께 적습니다.
- 운영자가 처리한 민원은 정확도에서 빠집니다(모델 정답으로 세지 않음).
